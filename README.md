# Parking System Client – לקוח React

לקוח React למערכת הקצאת החניה ([parking-system-server](../project_dotnet), ASP.NET Core). עיצוב כהה בהשראת חניון בלילה (בטון, נורות ענבריות, ירוק של שלט "פנוי"), בעברית ו-RTL.
ליבת המסך הראשי היא **תוכנית חניון אינטראקטיבית (SVG)** שבה בוחרים מקום ומזמינים אותו מול השרת האמיתי.

## המסכים
| מסך | מי רואה | מה הוא עושה |
|---|---|---|
| **התחברות / הרשמה** | כולם | `POST /api/tokens`, `POST /api/users` (נוצר עובד). ולידציה מיידית לפי כללי השרת, שגיאות 400 לפי שדה, 401, 409, 429 עם זמן המתנה. ה-JWT נשמר ב-`sessionStorage` |
| **חניון** (ראשי) | עובד, מנהל | תוכנית לפי קומה, פס תאריכים, סינון (קוד, מאפיין, "רק פנויים"), מקרא ולוח פרטים. עובד מזמין (`POST /api/reservations`) ומבטל; מנהל צופה בלבד. התאריך ברירת מחדל הוא היום, ולוח שנה לבחירת תאריך אחר. חלופה נגישה: תצוגת "רשימה", Tab/Enter וגם מקשי החצים במפה. בנייד לוח הפרטים הוא פס קומפקטי |
| **ההזמנות שלי** | עובד | `GET /api/reservations/mine` עם עימוד מהשרת, לוח חודשי של ההזמנות הפעילות, פרטים (`GET /api/reservations/{id}`), ביטול עם אישור |
| **ניהול מקומות** | מנהל | יצירה, עריכה, הפעלה/השבתה והוצאה משימוש. חיפוש, קומה, מאפיין, סטטוס, מיון ועימוד מתבצעים בשרת |
| **כל ההזמנות** | מנהל | `GET /api/reservations` עם עימוד וביטול |

## כנות לגבי הנתונים
- המפה מציגה את מצב המקומות **בעת הטעינה האחרונה** מהשרת, ואינה בזמן אמת (אין push בשרת). יש כפתור רענון.
- השרת אינו מחזיר תוכנית קומה: המיקום של כל מקום בציור נגזר מקוד, קומה ומאפיינים. הציור סכמטי ואינו מיקום פיזי.
- אין מחיר בשרת, ולכן אין מחיר בממשק. אין עדכון הזמנה (מבטלים ומזמינים מחדש). אין סינון הזמנות בשרת.
- "ההזמנה שלי" במפה נגזרת מ-100 ההזמנות האחרונות של המשתמש.
- **409** מוצג כהודעה כתומה בלוח הפרטים עם הסבר מהשרת, והנתונים מתרעננים. 401 מנתק (וגם פקיעת ה-token מנתקת אוטומטית), 403 מוצג כהרשאה, 429 עם זמן המתנה.

## הפעלה מקומית
דרישות: **Node.js 22.12 ומעלה**, והשרת רץ (ראו את ה-README של השרת).

```bash
npm install
npm run dev          # http://localhost:5173
```

כתובת השרת נקבעת ב-`VITE_API_URL`. ללא הגדרה זו `http://localhost:5258` (השרת המקומי). להגדרה אחרת, העתיקו `.env.example` ל-`.env`.
השרת מתיר לקרוא לו מ-`http://localhost:5173` (הגדרת `Cors:AllowedOrigins` ב-`appsettings.Development.json` של השרת).

## בדיקות
```bash
npm test             # 64 בדיקות: שכבת ה-API (fetch מדומה), שגיאות, תאריכים, ולידציה, פריסת המפה, ובדיקות ממשק (jsdom) להזמנה, 409, 401, לחיצה כפולה, מקלדת והרשאות. לא צריך שרת
npm run build        # בנייה לייצור
npm run e2e          # זרימה מלאה מול שרת חי (הרשמה, pagination, הזמנה, 409, 6 משתמשים במקביל, CORS)
```
בדיקות היחידה אינן בדיקה מול שרת אמיתי. `npm run e2e` יוצר משתמשים והזמנות בבסיס הנתונים של השרת, ולכן מומלץ להריץ אותו מול בסיס נתונים לבדיקות. כתובת אחרת: `E2E_API_URL=https://... npm run e2e`.

**שרת מדומה לפיתוח בלבד:** `node scripts/dev-mock-api.mjs` מרים שרת בזיכרון שמחקה את החוזה (פורט 5258, משתמשים `employee@mock.local` ו-`admin@mock.local`, סיסמה `MockPass123`), כדי לראות את הממשק בלי PostgreSQL. הוא אינו חלק מהבנייה ואינו מחליף בדיקה מול השרת האמיתי.

## העלאה ל-Render (Static Site)
> הלקוח נפרס **אחרי** השרת, כי הוא צריך את כתובת השרת.

1. העלו את התיקייה הזו ל-repository נפרד ב-GitHub.
2. ב-Render: **New > Blueprint** ובחרו את ה-repository. הקובץ `render.yaml` מגדיר אתר סטטי (`npm ci && npm run build`, תיקיית פרסום `dist`).
3. כשתתבקשו, הזינו `VITE_API_URL` = הכתובת של שירות השרת ב-Render, בלי `/` בסוף.
4. אחרי שהלקוח עלה, העתיקו את כתובתו (`https://<שם>.onrender.com`) לשרת: **Environment > `Cors__AllowedOrigins`**, ושמרו (השרת יופעל מחדש). בלי זה הדפדפן יחסום את הקריאות לשרת (CORS).

או ידנית, בלי Blueprint: **New > Static Site**, Build Command `npm ci && npm run build`, Publish Directory `dist`, ומשתנה סביבה `VITE_API_URL`.
הניווט מבוסס hash (`#/reservations`), ולכן אין צורך בהגדרת rewrite באתר הסטטי.

## אבטחה
- אין בקוד או ב-Git שום סוד. `VITE_API_URL` היא כתובת ציבורית, והיא נכנסת לקוד שרץ בדפדפן.
- ה-token נשמר ב-`sessionStorage` (נמחק בסגירת הלשונית). כשהשרת עונה 401 או כשה-token פג, הלקוח מנתק את המשתמש.
- ההרשאות נאכפות **בשרת**. הסתרת כפתורים וניווט לפי תפקיד בלקוח הם נוחות בלבד.
- יומן הקריאות הפנימי אינו שומר גוף בקשה, פרמטרים, token או סיסמאות.

